弱电工程管理平台 · UI 美化方案

基于对全部 23 个前端组件、三种角色（甲方 / 工程师 / 管理员）20 余个真实界面的逐屏走查而制定。目标：在不改动任何业务逻辑的前提下，用一套设计令牌（Design Token）+ Element Plus 主题定制 + 公共组件，让平台从「能演示的原型」变成「可商用的专业 B 端产品」。

1现状问题诊断（逐屏走查结论）

共性根因：全站使用 Element Plus 默认主题，229 处颜色硬编码散落在各组件，无统一设计变量；统计卡、状态标签、空状态、页面标题各写各的，导致视觉不统一、改一处无法收敛全局。

1.1 全局性问题（出现于每个页面）

问题具体表现（截图实证）
色彩体系混乱主色是 Element 默认蓝 #409EFF，首页/钱包又用同一套「蓝→绿廉价渐变」；状态色绿/蓝/灰/橙随手写，全站共 229 处硬编码色值、0 个统一变量。
统计卡布局错误首页看板、我的投标、个人/工程师看板、后台概览的 KPI 卡片全部纵向堆叠成一列（响应式栅格断点写错），每张卡又高又空，一屏看不全数据。
状态表达弱「已完成 / 已中标 / 履行中」等状态标签底色发白、字号小；我的投标里状态只剩一个对勾图标没有文字；后台用户表「状态」表头被挤出截断。
表格裸奔列表页（我的工程/合同/投标/消息/后台 8 个表）全是默认表格：表头灰、行高大、斑马纹无、列宽不控（投标时间「2026-0」换行截断）、操作按钮大小不一、多按钮挤一格。
缺公共骨架无统一页头（标题+说明+操作区）、无面包屑、无空状态规范（默认纸箱插画）、无加载骨架屏、无结果反馈统一样式。
导航缺陷品牌区只有一个小图标；窗口稍宽时菜单被折叠成「…」三个点；消息铃铛无未读时是灰圈；移动端没有底部导航。

2设计定位与原则

定位：工程行业可信协同平台的 B 端专业感 —— 让甲方觉得「钱托管在这里放心」、让工程师觉得「找活干活顺手」、让管理员觉得「审核处置高效」。

  • 可信优先：以沉稳科技蓝为主色，去除娱乐化的蓝绿渐变；资金、合同相关界面克制、规整、可追溯。
  • 效率优先：信息分层（页头标题 → 筛选区 → 数据/表格 → 操作），同类操作位置固定，一屏完成核心任务。
  • 统一优先：颜色/字号/间距/圆角/阴影全部走 Token，状态标签、按钮、空状态全站一个样。
  • 移动优先的现场场景：打卡、拍照、日志、报验是工程师在工地用的，按手机单手操作设计。
  • 只换皮不动骨：不改接口、不改数据结构、不改交互流程主干，纯展示层重构，回归测试可直接复用。

4.5 空状态 / 加载 / 反馈

  • 空状态：统一线性插画（按场景：空工程/空投标/空消息/空合同）+ 一句话说明 + 主操作按钮（如「去发布第一个工程」），替换默认纸箱图。
  • 加载：表格/卡片首次加载用骨架屏（灰块占位），按钮提交用 loading + 防重复点击。
  • 反馈：成功/失败统一 ElMessage 样式与措辞；资金、驳回、终止等不可逆操作用 ElMessageBox 二次确认，说明后果。
